#+TITLE: mep-wm feature-parity roadmap (vs mwm)
#+STARTUP: overview

Reference implementation: pkgs/mwm/mwm.cpp (17,380 lines, dwm derivative),
pkgs/mwm/mwm-cli.c (IPC client), pkgs/mwm/config.lua.example (target Lua API
surface). Rewritten 2026-08-06 after discovering the previous version of this
file was stale: it was written once right after an early commit and never
updated, so it still marked Phases 5-7 as TODO while several later commits
("Add bars and widgets", "implement project workspaces", "update project
picker", ...) had already landed most of that work. Keep this file in sync
going forward -- update it in the same commit as the feature, not later.

Skip/adapt anything that only makes sense for mwm's dwm-tag model, not
mep-wm's manual split/tab tree or per-project workspace model -- called out
per phase below where relevant.

* DONE Phase 1: Core WM mechanics
CLOSED: [2026-08-06]

Borders, floating/tiling, mouse move/resize, fullscreen, maximize, zoom,
kill client, EWMH (_NET_SUPPORTING_WM_CHECK/_NET_SUPPORTED/_NET_CLIENT_LIST/
_NET_ACTIVE_WINDOW), configurable mfact/nmaster. Directional focus
(focus_direction, Mod4+hjkl) is also done, despite an earlier note in this
file claiming otherwise.

* DONE Phase 2: Multi-monitor (Xinerama)
CLOSED: [2026-08-06]

Xinerama enumeration with mirror dedup, per-monitor arrangement of the
active workspace, Mod4+,/. focus/move-window-between-monitors, geometry
refresh on root ConfigureNotify.

* DONE Phase 3: System tray (XEMBED)
CLOSED: [2026-08-06]

_NET_SYSTEM_TRAY_S0 ownership + MANAGER broadcast, dock request handling,

* DONE Phase 4: Bar upgrade (Xft fonts, styled tags, task list)

* DONE Phase 5: Lua config + IPC socket
CLOSED: [2026-08-06]

Lua embedded via liblua, ~/.config/mep-wm/config.lua loaded on startup and
on reload (Mod4+r), errors logged-and-continued rather than crashing the WM.
Unix-socket IPC server at $XDG_RUNTIME_DIR/mep-wm-$DISPLAY.sock (mep-wm-cli
client), blocking one-client-at-a-time inside the main loop -- same
tradeoff mwm makes, not yet made non-blocking/multiplexed.

mwm.* Lua API surface implemented in src/x11_backend.cpp's initialize_lua():
set_terminal, set_mfact, set_nmaster, set_snap, set_gaps, set_border_width,
rule, keybind (spec, fn, [description]), mousebind, widget, exec,
zoom, toggle_floating, kill_client, scratchpad_set, scratchpad_toggle,
toggle_bar, set_layout(name), cycle_layout([direction]), list_projects,
current_project, switch_project(path), agent_command(cmd), theme(table).
Plus mep-wm-only additions with no mwm equivalent: todo/todo_toggle/
todo_remove/todo_clear_completed, notify.

Config reload (Mod4+r) drops and re-registers all Lua-side rules/keybinds/
mousebinds/widgets/themes, restores compiled defaults, unconditionally
ungrabs *and* re-grabs both keys and mouse buttons (root/bar/every managed
window) before re-running config.lua, so a reload that removes a binding
doesn't leave a stale X-server grab behind. Live window/workspace state is
untouched by a reload.

** Deliberately adapted rather than ported 1:1
- *Layout naming*: mwm's tile/floating/monocle map to mep-wm's own
  MasterStack/Manual/Monocle model (Manual is mep-wm's BSP/tab-tree layout,
  which mwm doesn't have at all). mwm.set_layout("tile"|"manual"|"monocle")
  and mwm.cycle_layout() use mep-wm's own 3 modes; there is still no
  mwm.layout({arrange=fn}) custom-tiling-algorithm hook (real gap, see
  below) -- would need a Lua-callable arrange(clients, area) dispatch
  analogous to mwm.cpp:6897-6940, not yet ported.
- *mwm.theme()*: mwm's table shape is {topbar={normal=,selected=},
  topbar_light={...}} (separate dark/light tables with fg/bg/border each).
  mep-wm's bar only ever had one fg/bg/selected triple, cycled through a
  fixed palette list (click/scroll the theme widget, or now Mod4+Shift+t).
  mwm.theme({name=, fg=, bg=, selected=}) adds/replaces one cyclable entry
  in that same list rather than introducing a separate light/dark axis.
  There is still no xdg-desktop-portal dark/light auto-detection (mwm's
  system_prefers_dark, mwm.cpp:5545) -- real gap if that matters later.
- *mwm.agent_command()*: launches the configured agent (default "claude")
  in its own terminal via Ctrl+Enter in the project picker, rather than
  trying to splice it into mep-wm's arbitrary user-configured
  config_.terminal launch expression.

* DONE Phase 6: Window rules, scratchpad, workspace-per-project
CLOSED: [2026-08-06]

Window rules (class/instance/title substring match -> floating and/or
workspace, applied at manage() time, Lua-driven via mwm.rule()). Scratchpad
(Mod4+minus toggle, Mod4+Shift+minus designate; survives between toggles by
re-tagging rather than unmapping). Workspace-per-project: each project gets
its own 9 numbered workspaces (src/x11_backend.cpp's Project struct),
created/switched via the project picker (Mod4+i recent, Mod4+o active-only)
or mwm.switch_project(path) from Lua/mwm-cli.

** Known gap: named workspaces
mwm workspaces carry a name (mwm.workspaces({...}), mwm.focus_workspace
(name), mwm.list_workspaces()); mep-wm's are still plain numeric indices
(kWorkspaceCount = 9, switched via Mod4+1..9). Not ported -- would need a
real design decision (a name field on Workspace, IPC/Lua surface for it,
and reconciling with the per-project workspace model) rather than a
mechanical port, and nothing currently using mep-wm depends on named
workspaces the way mwm's own config/scripts do.

* DONE Phase 7: Desktop-shell layer (substantially complete)
CLOSED: [2026-08-06]

This turned out far more complete than earlier phases assumed -- most of it
had already landed by the time of this rewrite:

- *Widget bar*: clock, cpu/mem/disk/load (/proc), battery/backlight
  (sysfs), volume/mic (amixer subprocess), wifi/bluetooth (nmcli/
  bluetoothctl/rfkill), git (reads .git/HEAD directly, no subprocess),
  media (playerctl), keyboard layout, theme -- all implemented, all with
  click/scroll actions where it makes sense. Custom Lua widgets via
  mwm.widget({name=, update=, click=, highlight=}).
- *D-Bus notification daemon*: implements org.freedesktop.Notifications
  (Notify/CloseNotification/GetCapabilities/GetServerInformation +
  NotificationClosed signal), self-contained in src/x11_backend.cpp.
- *Side panels*: notifications, todos (mwm.todo() API), agent status
  (reads $XDG_RUNTIME_DIR/mwm-agents/*.json, matching mwm's coding-agent
  status-file convention), keybinding help (now dynamically generated from
  a hand-maintained compiled-binding list plus live Lua keybind
  descriptions -- Mod4+Shift+slash, previously a static stale 8-line list
  with no keybind), and a generic info panel (wifi/bluetooth/media/
  keyboard/theme sub-panels, each with click actions).
- *Pickers* (all built on shared fuzzy_score/launcher overlay infra):
  application launcher (Mod4+p), project/active-project pickers (Mod4+i/o,
  Ctrl+Enter also launches the configured coding agent), window switcher
  (Mod4+w, fuzzy-jumps to any window across the current project's
  workspaces), theme picker (Mod4+Shift+t, lists every cyclable theme
  including Lua-registered ones).

** Known gaps (not ported -- scoped out, not forgotten)
- *Wallpaper picker* (mwm's Mod4+Shift+w, PickerModeWallpaper,
  mwm.cpp:1096/2247): mep-wm has no wallpaper-setting feature at all
  (no feh/hsetroot integration). Would be new functionality, not just a
  picker UI, so scoped out of this parity pass.
- *SSH host picker* (mwm's Mod4+e, PickerModeSSH, mwm.cpp:1097/2249):
  fuzzy-jump into a Host from ~/.ssh/config. Same shared launcher infra as
  the window switcher would make this cheap to add later; just not done
  yet.
- *Combined picker* (mwm's PickerModeCombined, projects+apps fuzzy-matched
  in one list): mep-wm keeps these as separate modes (Mod4+p vs Mod4+i/o).
- *mwm.layout({arrange=fn})* custom tiling algorithms from Lua: not ported
  (see Phase 5 adaptation note above).
- *cfact* (per-client weight within a master-stack column) and
  *resizebydir* (Mod4+Shift+hjkl resize-by-direction, which depends on
  cfact): not ported. mep-wm's master-stack columns are still evenly
  split; Mod4+Shift+hjkl instead resizes manual-mode panes, which doesn't
  need cfact.
- *Mod4+0 / Mod4+Shift+0* (view-all-workspaces / tag-on-all-workspaces):
  structurally tied to mwm's dwm bitmask-tag model; has no equivalent in
  mep-wm's one-workspace-per-window model.
- *Mod4+Shift+colon* interactive Lua command prompt: mep-wm has the IPC
  socket for scripted eval (mep-wm-cli) but no on-screen interactive REPL
  bound to a key.
- xdg-desktop-portal dark/light auto theme detection (see Phase 5 note).

None of the above are silently missing -- each was checked against
mwm.cpp and is listed here so the next pass doesn't have to re-derive it
from scratch.
